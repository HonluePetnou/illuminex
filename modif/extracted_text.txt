Correction 1 — R_moyen ignoré dans le calcul du CU

Fichier : src/utils/calculateLighting.js

Problème :
Le CU (Coefficient d'Utilisation) est calculé uniquement depuis k (indice du local) avec une table de 4 valeurs fixes. La valeur R_moyen — pourtant bien calculée dans l'interface Matériaux et sauvegardée dans formData.materiaux.rMoyen — est complètement ignorée.
Résultat : pour un bureau avec de bons matériaux clairs (R_moyen = 79%), le CU calculé est 0.50 alors qu'il devrait être 0.72. C'est la principale cause du résultat de 40 luminaires.

Solution :
Remplacer la table simplifiée par la formule du document de référence :
Formule correcte (méthode des cavités, IESNA Handbook) :

   CU = 0.9 / (1 + (1/k) × (1 − R_moyen))

   Avec R_moyen lue depuis formData.materiaux.rMoyen
   Valeur par défaut si absente : 0.65
   Bornes réalistes à appliquer : min 0.30, max 0.80

Vérification : bureau 7×6m, dalle 36W (3600 lm), R_moyen = 0.79 :
   Avant correction  →  CU = 0.50  →  N = 21 000 / (3600 × 0.50 × 0.70) = 17 luminaires
   Après correction  →  CU = 0.72  →  N = 21 000 / (3600 × 0.72 × 0.80) = 10 luminaires  ✅

Correction 4 — Projet sauvegardé impossible à relancer

Fichier : src/renderer.jsx

Problème :
Deux problèmes combinés dans handleOpenProject() :
Problème A — Quand un projet est rechargé, activeScreen n'est pas remis à l'étape 1. L'app reprend là où elle en était lors de la dernière session, sans recalculer la cascade depuis le début — ce qui provoque un état incohérent et le crash.
Problème B — La clé rMoyen est absente de defaultValues.materiaux. Au rechargement, si cette clé n'existait pas dans le projet sauvegardé, elle vaut undefined — ce qui fait planter calculateLighting (NaN ou N = Infinity).

Solution :
A — Dans handleOpenProject(), ajouter après setCurrentProject(fullProject) :

   setActiveScreen('dimensions')

   Cela force le retour à l'étape 1 à chaque ouverture de projet,
   ce qui garantit que toute la cascade est recalculée dans l'ordre.

B — Dans defaultValues.materiaux, s'assurer que rMoyen est présent :

   rMoyen: 0.65   ← valeur par défaut si absente du projet sauvegardé

Correction 5 — Borne 'Trop froid' décalée (mineure)

Fichier : src/utils/thermalComfort.js
Note : correction mineure — n'a aucun impact pour le contexte africain (on ne sera jamais 'trop froid' à Cotonou 😄)

Problème :
Selon le document de référence (tableau section 3.6 — EN 15251:2007), la borne 'Trop froid' est différente selon l'état des fenêtres :
